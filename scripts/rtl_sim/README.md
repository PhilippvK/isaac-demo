# Nailgun RTL benchmark execution

`flow_rtl_sim.sh EXPERIMENT_DIR` runs the extraction benchmark on the **generated
SCAIE-V core and extension RTL**. It supports CVA5 and VEX_5S, independently of
Vivado, FPGA part, or board. This is separate from CFU-Playground simulation.

## Normal flow

After tracing, generating RTL with HLS, and retargeting LLVM with Seal5:

```bash
source scripts/env.sh
source cfg/flow/paper/cva5_reuseio_mem_branch.env # or vex_5s_mem_branch.env
export RTL_SIM_VERILATOR=/path/to/verilator-5.040/bin/verilator
scripts/full_flow.sh crc32 latest rtl_sim_0
# The selection suffix must match the HLS and compiler artifacts:
scripts/full_flow.sh crc32 latest rtl_sim_0_filtered_selected
```

Set `RTL_SIM_ENABLE=1` to insert the matching simulation stage immediately after
each HLS stage in a normal full-flow invocation. Its default is disabled. The
retargeted compiler must already exist before that HLS stage. Explicit
`rtl_sim_0` stages always execute, regardless of `RTL_SIM_ENABLE`.

By default both `baseline` and `default` HLS variants run. Use
`RTL_SIM_VARIANTS=baseline` for a native-only run; `default`, `custom`, and
`shared` use the matching retargeted architecture. Every requested variant must
exist and pass; missing compilers/RTL are errors. Results live in
`EXPERIMENT_DIR/work/rtl_sim_SUFFIX[_isel_SELECTOR]/` including firmware,
build commands, UART output, simulator compilation log, `execution.json`, and
`summary.json`. Selected logs, firmware and results are also preserved in
`EXPERIMENT_DIR/rtl_sim_SUFFIX[_isel_SELECTOR]/`, outside the disposable build
folder. `report_0` links these measurements in the normal CI report. Use
`RTL_SIM_REPORT_DIR` to retain a report in a repository `reports/` directory.

### Benchmark runtime

The exported `run/compile_commands.json` is replayed. The benchmark sources,
MLIF main, result verification, optimization options, and selected instruction
selector are retained. GISel runs request strict selection so compiler failures
are reported instead of silently changing selectors. ETISS startup/trap/platform sources are replaced, and
the image is linked at `0x80000000` with 256 KiB RAM, an 8 KiB stack reservation,
and newlib UART/heap/exit services. The simulation returns success only after
an explicit exit-status write of zero. A disabled MLIF result check is rejected.

This rebuild is necessary: extraction ELF images use ETISS addresses and
semihosting. Their machine-code layout changes when linked for RTL. Rebuilt
firmware hashes and compile commands record exactly what was executed.

The current runtime supports the MLIF generic C benchmark entry point, including
Embench. Source/include paths must still exist. It does not reconstruct deleted
generated sources or additional CMake-linked frontend libraries. Floating-point
or compressed ISA builds must be rebuilt for an ISA supported by the chosen
core; the supplied target presets use RV32IM/ILP32. Images exceeding the RAM
budget fail to link; RAM accesses outside that budget fail simulation.

### Models and measurements

Vex uses AHB RAM with no wait states. CVA5 uses one-cycle synchronous local RAM
and a single-beat peripheral AXI responder. Both expose UART, simulation-cycle
and retirement counters, trap registers, and an exit-status register at
`0x60000000`. CVA5's generated byte-address wrapper is staged with full-width
addresses, and its injected memory width follows ISAAC's scaiev2 funct3 contract.
The original generated RTL is retained unchanged.

MLIF `Run Cycles` measures the actual benchmark region, excluding startup and
printing. `execution.json` also reports whole-program cycles. Cycle comparisons
are meaningful within one core/model; these are not FPGA timing estimates.
CVA5 retirement counts include SCAIE-V injected operations and should not be
interpreted as architectural ISE utilization. Simulation timeouts, traps,
unmapped bus accesses, build failures, and nonzero exits fail the stage.
`RTL_SIM_DATA_WAIT` adds AHB data wait cycles on Vex and spaces peripheral AXI
acceptance on CVA5; CVA5 local RAM retains its required one-cycle latency.
Use Verilator **5.040** (validated); the host's 4.038 cannot compile CVA5 interfaces.

## Overrides and low-level use

- `RTL_SIM_CORE`: `cva5` or `vex` (default: HLS core).
- `RTL_SIM_HLS_DIR`: HLS root containing `baseline`, `default`, etc.
- `RTL_SIM_RTL_DIR`: explicit generated RTL directory for a single variant.
- `RTL_SIM_COMPILE_COMMANDS`: alternate extraction export.
- `RTL_SIM_COMPILER`, `RTL_SIM_ARCH`: retargeted compiler/extended architecture.
- `RTL_SIM_BASE_ARCH`: optional native ISA override; `ABI` defaults to ILP32.
- `RTL_SIM_GNU`: GCC/newlib installation (default: ISAAC GNU installation).
- `RTL_SIM_OUTPUT_DIR`: simulator build destination override.
- `RTL_SIM_REPORT_DIR`: selected evidence destination (outside `work/` by default).
- `RTL_SIM_DATA_WAIT=0`, `RTL_SIM_MAX_CYCLES=100000000`, `RTL_SIM_TIMEOUT=600`, `RTL_SIM_JOBS=4`.

```bash
python3 scripts/rtl_sim/build_benchmark.py run/compile_commands.json firmware \
  --gnu install/gnu_cfu --path-map /old/checkout=/new/checkout
python3 scripts/rtl_sim/run.py --core vex --rtl hls/default/rtl \
  --firmware firmware/benchmark.bin --output simulation \
  --verilator /path/to/verilator-5.040/bin/verilator
```

### Simulator setup and effect probes

Install the pinned Verilator with autoconf, flex, bison, a C++ compiler, Perl,
Python, make and help2man available:

```bash
scripts/rtl_sim/install_verilator.sh "$PWD/install/verilator-5.040"
export RTL_SIM_VERILATOR="$PWD/install/verilator-5.040/bin/verilator"
```

The existing firmware probe builder accepts `--rtl-sim`, which replaces the
post-main idle loop with an exit-status write. Build a matching memory/branch/
store probe using `scripts/fpga_syn/firmware/build.py --rtl-sim ...`, then pass
its `firmware.bin` to `run.py`. These supplemental probes remain separate from
the extraction benchmark and its MLIF verification.
