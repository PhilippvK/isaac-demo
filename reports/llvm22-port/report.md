# LLVM 22 local port — verified local retargeting

The LLVM 22.1.8 CDFG compiler builds and locally retargets the existing
32-instruction CRC32 ISE set. The usable compiler is
`llvm-project-22/build/bin/clang`; set `LD_LIBRARY_PATH` to
`install/mgclient/lib` when invoking it. LLVM19 remains the default.

## Implemented

- Separate official LLVM 22.1.8 checkout (`llvm-project-22`), preserving LLVM19.
- CDFG pass, build integration and pipeline observation hooks ported to LLVM22.
  Removed the unused GISelKnownBits dependency; this analysis was renamed.
  Observer pass returns false because it does not mutate the MachineFunction.
- Fixed-BB/clone/provenance checks retained. Increased subtarget feature capacity
  retained for per-instruction extension sets. Existing narrow-expression
  selection policy retained while preserving LLVM22 truncation handling.
- Old Clang labels restriction and manual GPR register-bank workaround omitted:
  current upstream labels handling and generated register-bank mapping replace
  those old edits. No unsafe optional-ID dereference from the old header trace
  hack is carried over.
- Portable source patch: `cfg/seal5/llvm22-isaac.patch`. New source files included.
- Toolkit BB map decoder supports wire versions 2–5, 32/64-bit addresses, multiple
  ranges, optional callsite/hash/PGO payloads, and strict truncation/overflow checks.
  Existing internal `bb_map_decoder=2` provenance revision is retained; that value
  is not the wire-format version. Each BB is disassembled exactly once, using
  cached executable-section bytes to avoid rereading the ELF for every block.
- Local retargeting runner selects version profiles, typed M2-ISA-R, preserves
  build trees, avoids the redundant baseline build, and retains its log in output.
  `LLVM_MAJOR=22` selects the LLVM22 profile. Common defaults still select LLVM19.
  `SEAL5_BUILD_THREADS` limits compiler build concurrency.

## Compatibility verification

- 52 targeted Toolkit tests pass (`toolkit-tests.log`), including 31 BB map cases.
- Existing LLVM19 CRC32/SHA256 baseline BB tables match the previous decoder
  exactly: 21 functions / 52 and 72 blocks (`llvm19-bb-regression.log`).
- Real RV32 and RV64 LLVM19.1.7, LLVM20.1.8, LLVM21.1.8 and LLVM22.1.8
  compile/link/decode probes pass using
  `-fbasic-block-sections=labels`. Explicit `-fbasic-block-address-map` is rejected
  for RISC-V by all four drivers despite appearing in `--help`; keep the working
  labels flag. Probe results and exact commands are in `compat-probe-*.json`.
  LLVM19–21 emit version2 maps; LLVM22 emits version5 maps.
- Version profiles load correctly against current Seal5 for LLVM19–22.
- LLVM22 configures with CDFG enabled, RISCV, Release+assertions, Clang18 host.
  Initial compilation stopped on filesystem exhaustion. Space subsequently
  recovered; compilation resumed (`build-retry.log`). LLD then needed the omitted
  libunwind headers; after adding them, compilation resumed (`build-final.log`).
  No source failure inferred
  from the disk-full compiler crash.

## Completed local retargeting

The existing 32-ISE CRC32 set was retargeted locally in the same source and
build tree, with typed M2-ISA-R and matching PatternGen22. No retargeting service
or compiler container was used. Seal5 manages patch commits in this disposable
LLVM checkout. The baseline LLVM19 source/install remain unchanged.

- All 32 instruction definitions and patterns were generated and compiled.
- All 26 generated tests passed: 24 instruction-selection fixtures and two
  extension/attribute tests. Eight immediate-operand instructions have no
  autogenerated IR selection fixture; their runtime semantics are not established
  by these tests.
- Results: `local-retarget-tests-final.log`,
  `local-retarget/seal5_reports/test_results_compact.csv`, and
  `local-retarget/seal5.tar.gz` (exported models, patches, tests and settings).
- Eight focused Seal5 tests pass (`seal5-tests.log`).
- The main public M2-ISA-R parses all 32 source definitions (`main-m2-smoke.log`).
  Initial generation used the separate typed `M2-ISA-R-new` checkout; final tests
  and reports also loaded successfully with the main public checkout.

The shared `legalizer_split` patch was LLVM19-specific and failed on LLVM22.
Seal5 now generates this split from the selected source for LLVM20+, preserving
its actual legality rules. Focused unit cases pass, and generation succeeds on the
four official LLVM19–22 release source files (`legalizer-versions.log`).

Release+assertions with `LLVM_OPTIMIZED_TABLEGEN=ON` requested a separate native
build whose default docs/examples were absent from the sparse tree. Sparse
preparation patterns now include those directories. This run disables the
redundant native build and reuses the existing Release TableGen tool.

The runner pins CMake to the active Python interpreter: an incomplete unrelated
Python installation initially prevented lit from starting. Reduced builds now
include lit's `count` and `not` utilities. Lit output is captured even with quiet
console logging, and zero parsed test results fail the run. Report generation
uses the latest test attempt, so a failed earlier attempt cannot hide a later
successful result. These failures were fixed and the complete test suite rerun.

## Checks after retargeting

- Repeated RV32/RV64 compile/link/BB-map probes and both selectors' pipeline and
  live CDFG identity checks successfully against the retargeted compiler.
- Native RV32 and RV64 fixture `.text` hashes are identical before/after
  retargeting when XIsaac is disabled (`native-code-regression.json`).
- Actual CRC32 source, identical flags and the same ISE set emit six static
  custom-instruction sites on both LLVM19 and LLVM22: two each of custom15,
  custom17 and custom18 (`crc32-codegen-results.json`).
- All 52 Toolkit and eight Seal5 focused unit tests pass after final changes.
  Shell syntax and tracked diff whitespace checks also pass.

These checks found no regression in the tested scope. They do not measure dynamic
utilization or runtime speedup, prove all instruction semantics, or cover a full
branch/memory extension sweep. The 20/21 checks cover Toolkit compatibility;
only LLVM22 received the compiler CDFG source port in this task.

## Reproduction

For a fresh source checkout:

```bash
source scripts/env.sh
scripts/prepare_llvm22.sh
LLVM_MAJOR=22 scripts/flow_seal5.sh RUN_DIR
```

Preparation pins official LLVM22.1.8 and applies
`cfg/seal5/llvm22-isaac.patch`. Use a fresh `LLVM22_DIR` when repeating preparation:
the existing checkout now contains Seal5-generated commits, and preparation
intentionally rejects a different HEAD. Local retargeting expects the normal
flow input artifacts in RUN_DIR; see `scripts/flow_seal5.sh`.

The retained exact experiment can resume tests and export with:

```bash
SEAL5_START_AT=test reports/llvm22-port/run_local_retarget.sh
```

This helper sets `RESET=0`, preserves the build tree and pins the original typed
M2 checkout. Override `SEAL5_M2ISAR_DIR` to select the main public checkout.
Other explicit checkpoints are setup, models, build-tools, patterns,
build-final, export and reports. Resumption requires initialized saved settings.
Source revisions, implementation hashes and compiler fingerprints are recorded
in `source-versions.json`; retained submodule diffs are in this directory.

The LLVM20/21 probes verify Toolkit compile/map compatibility, not a CDFG port
of those compiler versions. Locally extracted Jammy compiler packages are
SHA256-checked against the apt.llvm.org package index; package versions, URLs
and dependencies are retained in `compat-compilers/packages.json`.

The first isolated database launch (direct binary, 512MiB cap) exited139 during
startup. The normal platform entry point with a 1GiB cap runs successfully;
all live checks use this isolated Memgraph2.14.1 endpoint at127.0.0.1:28764.
Compiler builds and retargeting run locally. The database is the only container
used for this port's verification.
